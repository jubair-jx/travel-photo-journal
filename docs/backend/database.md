# Database

Neon-hosted Postgres, accessed only through Prisma (ADR-0002). Tables and columns are snake_case in the database and camelCase in code (`@@map` / `@map`).

## Connections

| Variable            | Used by                          | Endpoint                                                       |
| ------------------- | -------------------------------- | -------------------------------------------------------------- |
| `DATABASE_URL`      | The running API (driver adapter) | Pooled                                                         |
| `DIRECT_URL`        | `prisma migrate` (via config)    | Direct                                                         |
| `DATABASE_URL_TEST` | The test suite                   | Compose Postgres locally, a service container in CI. Not Neon. |

Prisma 7 reads `DIRECT_URL` from `prisma.config.ts`; the schema file contains no URL. The runtime client is built with the `pg` driver adapter and the pooled URL.

## Schema (current)

### users

| Column               | Type         | Notes                                                                                                     |
| -------------------- | ------------ | --------------------------------------------------------------------------------------------------------- |
| `id`                 | uuid, PK     | Generated by Prisma                                                                                       |
| `email`              | text, unique | Stored trimmed and lowercased by the input schema                                                         |
| `password_hash`      | text         | argon2id                                                                                                  |
| `email_verified_at`  | timestamptz? | Null until the address is verified                                                                        |
| `two_factor_secret`  | text?        | `v1.<iv>.<tag>.<ciphertext>` (AES-256-GCM, ADR-0010); a pending secret until `two_factor_enabled` is true |
| `two_factor_enabled` | boolean      | Default false                                                                                             |
| `created_at`         | timestamptz  | Default now                                                                                               |
| `updated_at`         | timestamptz  | Maintained by Prisma                                                                                      |

### email_verification_tokens

| Column       | Type              | Notes                                                            |
| ------------ | ----------------- | ---------------------------------------------------------------- |
| `id`         | uuid, PK          |                                                                  |
| `user_id`    | uuid, FK to users | `ON DELETE CASCADE`; indexed                                     |
| `token_hash` | text, unique      | SHA-256 hex of the emailed token. The raw token is never stored. |
| `expires_at` | timestamptz       | Issue time plus 24 hours                                         |
| `used_at`    | timestamptz?      | Set when the token is consumed                                   |
| `created_at` | timestamptz       | Default now                                                      |

### refresh_tokens

| Column           | Type                        | Notes                                                           |
| ---------------- | --------------------------- | --------------------------------------------------------------- |
| `id`             | uuid, PK                    |                                                                 |
| `user_id`        | uuid, FK to users           | `ON DELETE CASCADE`; indexed                                    |
| `token_hash`     | text, unique                | SHA-256 of the cookie value; the raw token is never stored      |
| `expires_at`     | timestamptz                 | Issue time plus 7 days                                          |
| `revoked_at`     | timestamptz?                | Set on rotation, logout, or theft response                      |
| `replaced_by_id` | uuid?, FK to refresh_tokens | The successor issued at rotation; `ON DELETE SET NULL`; indexed |
| `created_at`     | timestamptz                 | Default now                                                     |

A session is the chain of rows linked by `replaced_by_id`. Rotation is a conditional UPDATE (`revoked_at IS NULL AND expires_at > now`) followed by creating the successor, in one transaction. See ADR-0009.

### photos

| Column        | Type              | Notes                                                                          |
| ------------- | ----------------- | ------------------------------------------------------------------------------ |
| `id`          | uuid, PK          |                                                                                |
| `user_id`     | uuid, FK to users | `ON DELETE CASCADE`                                                            |
| `name`        | text              | 1 to 120 characters (enforced by the input schema)                             |
| `location`    | text              | 1 to 120 characters                                                            |
| `description` | text              | 1 to 2000 characters                                                           |
| `summary`     | text?             | Server-generated from the description; null when unavailable                   |
| `image_key`   | text              | Storage object key `photos/<user id>/<random id>.<ext>`; never sent to clients |
| `image_mime`  | text              | Detected from the file's bytes                                                 |
| `created_at`  | timestamptz       | Default now                                                                    |
| `updated_at`  | timestamptz       | Maintained by Prisma                                                           |

The index on (`user_id`, `created_at`) serves the list query (a user's photos, newest first). Every query that touches a photo filters on both `id` and `user_id` (ADR-0007). Deleting a user cascades to their rows but not to files in storage; there is no account-deletion feature yet.

## Design notes

- **Uniqueness lives in the database.** Duplicate registration is detected by the unique index on `users.email` (Prisma error `P2002`), not by a read-then-write check, so concurrent registrations cannot both succeed.
- **Single-use tokens are enforced by one conditional UPDATE** (`WHERE token_hash = ? AND used_at IS NULL AND expires_at > now`). The row count says whether this caller won.
- **Lowercasing is done in the application** (input schema) rather than with `citext`. Every write path goes through the schema, and this avoids a Postgres extension on the hosting side.
- **`timestamptz` everywhere**, so values are unambiguous across servers and time zones.
- **Hashing tokens with SHA-256 rather than argon2**: tokens are 256-bit random values, so there is nothing for a slow hash to protect, and lookups need a deterministic value to query by.
- Used tokens are kept (not deleted) as a record; unused tokens are replaced when a new one is requested.

## Migrations

- Create (development): `DIRECT_URL=<direct url> npx prisma migrate dev --name <change>` from `backend`.
- Apply (release): `cd backend && npm run prisma:deploy`.
- Tests apply pending migrations to the test database automatically before the suite runs.
- The generated client is not committed; `cd backend && npm run prisma:generate` produces it, and the test, typecheck and build scripts do so first.

| Migration                            | Contents                             |
| ------------------------------------ | ------------------------------------ |
| `init_users_and_verification_tokens` | `users`, `email_verification_tokens` |
| `add_refresh_tokens`                 | `refresh_tokens`                     |
| `add_photos`                         | `photos`                             |
